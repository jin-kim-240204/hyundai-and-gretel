# Pull Request

루트 AGENTS.md와 현재 작업 기록을 읽는다. 본문 작성만 요청받으면 로컬 초안까지 만든다. 실제 PR 생성·수정은 해당 사용자 요청 범위에서 수행하며, 스킬 추가 요청은 실행 권한이 아니다.

## 대상과 변경 확인

- `git status --short`, `git branch --show-current`, `git remote -v`로 저장소와 브랜치를 확인한다. 원격 URL의 인증정보는 출력에 노출하지 않는다.
- base는 사용자 지정 또는 대상 저장소의 기본 브랜치를 확인해 정한다. `main`으로 고정하지 않는다. 필요한 원격 참조가 없거나 오래되었다면 조회를 갱신한다.
- `git log <base>..HEAD --oneline`, `git diff <base>...HEAD`로 PR 전체 변경을 읽는다. 미커밋 변경은 PR에 포함된 것처럼 설명하지 않는다.
- 대상 저장소와 head/base가 같은 열린 PR을 조회한다. 이미 있으면 중복 생성하지 말고 URL을 알린다. 수정 요청이 있으면 그 PR을 갱신한다.
- base 브랜치에서 작업 중이면 목적에 맞는 작업 브랜치를 만든다. 파일·브랜치·대상 저장소가 모호하면 초안을 준비한 뒤 필요한 정보만 확인한다.
- [pleos-verify](../pleos-verify/SKILL.md)에 따른 검사 결과와 `docs/work/` 근거를 확인한다. UI·차량 제어 변경은 해당 화면·런타임 증거를 연결하고, 필수 미검증이나 실패가 남으면 완료로 표현하지 않는다.

## 제목과 본문

제목은 `fix(app): 화면 복귀 시 상태 복원`처럼 변경 결과를 한국어로 쓴다. 사내 티켓 접두사·라벨·리뷰어를 추정하지 않는다.

저장소에 PR 템플릿이 있으면 따른다. 없으면 아래 구조로 필요한 내용만 작성한다. 작은 변경은 각 항목을 짧게 쓰고, 변경 이유와 사용자에게 보이는 결과를 먼저 설명한다.

```markdown
## 설명

해결한 문제와 변경 후 동작

## 변경 사항

- 주요 변경

## 검증

- PASS / FAIL / NOT_TESTED / N/A와 명령·증거
- 작업 기록: docs/work/<작업명>.md
- UI 변경이면 화면 증거, 차량 제어면 지원·권한·오류 시나리오 결과

## 검토 요청

집중해서 볼 결정·트레이드오프·남은 제한. 없으면 해당 없음
```

## 생성·수정과 확인

연결된 GitHub 도구가 필요한 기능을 지원하면 우선 사용하고, 부족하면 `gh`를 사용한다. 저장소·base·head·제목·본문을 명시한다. CLI 본문은 임시 파일로 작성하고 `--body-file`로 전달한다.

PR 생성 요청에 필요한 작업 브랜치 push는 요청 범위 안에서 수행한다. push 권한을 제한한 지시가 있으면 그 경계를 따른다. 실패·필수 미검증이 남은 PR은 draft로 생성하고 이유를 본문에 적는다. 실패한 생성 요청을 재시도하기 전 기존 PR 생성 여부를 조회한다.

merge·배포·리뷰 요청 전송은 별도 지시가 있을 때만 수행한다. 생성·수정 후 대상 저장소, base/head, 본문, draft 상태를 다시 조회하고 PR URL과 검증 제한을 알린다.
