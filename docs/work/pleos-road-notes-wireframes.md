# hyundai-and-gretel · Pleos Connect 와이어프레임

2026-11-11 · 화면 구조와 인터랙션 검토안 · 앱 코드 변경 없음

## 1. 서비스와 대표 레이아웃

앞서 지나간 운전자가 남긴 도로 상황을, 같은 경로와 진행 방향으로 뒤따르는 운전자가 가까워졌을 때 받는다. 시작 화면에서 위치가 **지나온 위치에 쪽지를 남기고, 가까운 쪽지를 받는 데 사용된다**고 설명한다. 저장 위치는 제보 처리 시점 기준 약 30초 전의 실제 표본이다. 짧은 이력에서는 가장 오래된 유효 표본을 쓰며, 첫 신선한 표본도 제출 가능하다. 사용자 화면에는 정확한 목격 위치나 남은 거리처럼 읽힐 표현을 넣지 않는다.

**대표안은 ‘도로 쪽지’ 단일 열 화면이다.** 상단 앱 제목 → 핵심 쪽지 또는 현재 필요한 안내 → 수집 상태·제보 결과 → 허용되는 경우에만 행동 버튼. 수신 카드와 저장 결과의 자리를 분리해 동시에 발생해도 수신 카드가 유지된다. 평소에는 빈 상태가 같은 카드 자리를 사용한다. A와 B는 이 화면을 그대로 사용하며, 저장 성공 후 패널을 닫아도 성공 문구가 보인다. B 역할 전환은 A의 결과 표시를 B로 가져오지 않는다.

| 앱 창 | 콘텐츠 배치 | 디버그 배치 |
| --- | --- | --- |
| 전체 앱 창 | 왼쪽 정렬한 단일 열에 가독 폭을 확보한다. 넓은 여백은 유지하며 수신과 상태의 시선 순서는 고정한다. | 앱 경계 안 오른쪽에서 겹쳐 열고, 제품 카드가 패널에 가려지면 화면 표시 완료 처리를 보류한다. |
| 분할 창 | 가용 폭에 맞춰 카드와 상태를 세로로 쌓는다. 별도 사이드바 없이 같은 컴포넌트를 쓴다. | 앱 창 안의 패널로 열고 기본 조작을 세로로 재배치한다. |
| 가장 작은 지원 창 | 분류 아이콘·라벨과 본문을 먼저 확보한다. 보조 안내를 먼저 접고 주요 행동을 한 줄씩 놓는다. 규제 또는 공간 때문에 핵심 본문을 안전하게 표시할 수 없으면 표시 완료 처리를 보류한다. | 닫기 고정. 기본 조작을 먼저 노출하고, 스크롤이 필요하면 허용된 debug 환경에서 패널 내부에만 적용한다. |

Connect-S 전체/분할과 Connect-W 넓은/좁은 창은 OS가 배정한다. Driving view·GNB·상태 표시줄은 와이어프레임 경계 밖이다. 시스템 패널이 앱을 덮으면 시스템이 위에 표시된다. 작은 창은 좁은 가용 영역에 대한 설계 상태이며, 별도 Pleos 창 모드로 가정하지 않는다.

## 2. 제품 화면과 상태 전이

동봉 와이어프레임 P1–P9는 동일한 화면의 예시다. 시작·중지·설정·다음 쪽지 버튼은 시스템 제한과 아래 적용 조건에 따른다.

| 화면 요소 | 표시 및 데이터 | 행동과 상태 전이 |
| --- | --- | --- |
| P1 시작 전 | “앞서 지나간 운전자의 도로 쪽지”와 위치 사용 목적 | 허용 시 [시작] → 시스템 위치 권한 확인 → 서비스 시작 중. 권한 요청 중 화면을 벗어나거나 시작 의도가 취소되면 자동 시작하지 않는다. |
| P2 권한 부족 | “위치 권한이 필요해요.” 최초 요청 가능 여부와 권한 설정 안내를 구분 | 허용 시 [위치 허용] 또는 [설정 열기]. 복귀 후 권한을 재확인한다. 규제 중에는 “주차 후 위치 권한을 확인해 주세요.” |
| 위치 사용 불가 | 시작 중 “위치를 켜는 중이에요” / 대기 “위치 신호를 기다리는 중이에요” / 일시 불가 “현재 위치를 확인할 수 없어요” / 미지원 “이 환경에서는 위치를 사용할 수 없어요” / SDK 실패 “위치 연결에 실패했어요” | 일시 불가는 기존 등록 유지와 새 유효 표본 복구, 허용 시 중지. 실패는 정리 후 허용 시 [다시 시작]. 미지원에서는 재시도 대신 이유만 표시. 권한과 SDK 상태를 별도 입력으로 사용한다. |
| P3 정상 대기 | 유효 위치 수신 상태와 표시할 새 쪽지 없음. “도로 쪽지 받는 중”과 “새로 받은 쪽지가 없어요.” | 수신 또는 제보 이벤트에 따라 슬롯 갱신. [중지]는 제품·디버그가 같은 명시적 중지 경로를 호출한다. |
| P4 제보 처리 | 유효한 입력이 처리 경로에 들어오면 “제보를 저장하는 중이에요.” | 결과 슬롯에서 지연 피드백. 반복 제출 차단. 요청·세션을 연결해 이전 역할의 결과가 나타나지 않게 한다. |
| P5 저장 성공 | Room 커밋 확인 후 “도로 쪽지를 남겼어요.” | 패널 닫힘과 무관하게 제품에 표시. 이 슬롯은 다음 제보·시연 역할 전환에서 교체/정리하는 안이다. 시스템 Gleo 콜백 전달 실패는 별도 진단으로 남기며 커밋을 취소하지 않는다. |
| P6 저장 실패 | “위치를 확인한 뒤 다시 제보해 주세요” / “쪽지를 저장하지 못했어요. 다시 제보해 주세요.” | 표본 부족·유효하지 않은 위치·저장 실패에 맞는 문구. 저장되지 않은 쪽지로 B의 새 대상이 생기지 않는다. 자동 재시도 없음. |
| P7 수신 | 인라인 카드. △ + “주의”(WARNING), ⓘ + “정보”(INFORMATION), 짧은 제보 본문. 아이콘은 자리표시자. | 앱이 실제 보이고 허용된 경우에만 렌더 후 표시 처리. 카드 자동 클릭, 음성, 팝업, 시스템 알림 없음. 거리나 위험 보장 문구 없음. |
| P8 여러 쪽지 | 동일 후보 묶음은 계획의 전방 거리순 처리로 첫 한 건을 표시. 나머지는 PENDING으로 보관 | 현재 카드를 자동 스크롤하거나 반복 교체하지 않는다. 조작 허용 상태에서만 [다음 쪽지] 한 번으로 같은 슬롯 교체. 규제 중에는 탐색 버튼과 대기 건수를 생략하는 안. 새 후보가 더 가까울 때 선점 여부와 동률은 미확정. |
| 복귀·재생성 | 서비스 상태에 다시 연결하고 현재 사용자의 PENDING을 확인 | 연결 전에는 “수집 상태 확인 중”으로 표시해 현재 VM의 초기 STOPPED 값으로 시작 화면이 깜박이지 않게 한다. 표시 직전 규제·가시성·유효성을 다시 확인. 같은 카드를 새 수신으로 재생하지 않는다. |

수신 이력은 원본과 별도이며 `noteId + recipientId` 유일성으로 반복 콜백·재접근을 막는다. 처음 실제로 보인 뒤 DISPLAYED를 기록한다. 화면 표시 직후 ACK 전 프로세스가 종료되면 복귀 때 한 번 더 보일 수 있다. 수신 이력 한 건 보장과 화면 렌더의 원자성은 별개다. 창 재생성 시 기존 카드의 시각적 복원은 새 수신 연출 없이 처리하는 제안이다.

Gleo는 목표 입력 경로다. 현재 브랜치의 제품 버튼에는 넣지 않는다. 기존 계약의 `content/category/locationMode=CURRENT_ROAD`를 확인하되 trim 후 최대 500자 입력 한도는 표시 한도로 사용하지 않는다. P7·P8의 문구는 짧은 예시다. 긴 원문을 위한 한국어 길이·말줄임·부정어 또는 위치 조건 손실·상세 공개 정책은 별도 합의가 필요하다. 그전에는 짧은 fixture로 시연하고, 적합한 짧은 본문이 없는 장문은 제한 상태에서 공개하지 않는 안으로 둔다. 터치 입력이 꼭 필요하면 주차 중 고정 문구 프리셋을 별도 제안으로 검토한다. 출시·심사에서 요구하는 터치 경로와 앱 설치 유형은 확인 대상이다.

## 3. 디버그 오버레이

D0은 P7처럼 패널이 완전히 사라진 상태다. debug에서만 앱 내부에 진입점을 둔다. 전체 제품 화면 캡처가 필요하면 **앱 제목 길게 누르기**를 시연자에게 알려주는 방식으로 별도 고정 버튼을 생략하는 제안이다. 규제 상태를 확인할 수 있고 시연 조작이 허용될 때만 진입한다. D1 기본 펼침 → D2 상세 펼침은 같은 패널의 접기 영역이다. 닫기·열기·상세 접기는 추적과 외부 입력을 변경하지 않는다. 패널이 열린 채 규제가 바뀌면 조작을 즉시 잠그고 시스템의 앱 표시 결정을 따른다. OS 전역 오버레이 권한은 요구하지 않는다.

| D1 기본 조작 | 활성 조건·처리 | 결과와 실패 |
| --- | --- | --- |
| 새 시연 초기화 | [새 시연 초기화] → 앱 창 안 확인 영역. “이 시연의 합성 쪽지와 수신 이력을 삭제하고 위치 버퍼와 접근 등록을 지웁니다.” [취소] [초기화] | 완료 후 “초기화 완료. GPS 모드를 확인하고 A 시작 위치를 설정하세요.” 제안 기본값은 초기화 완료 후 수집 중지 상태. 외부 스크립트가 계속 돌고 있으면 재정렬 안내. 실패 시 ‘완료’ 표시 없이 재시도 가능한 이유 표시. |
| A 시작 위치로 설정 | 지정된 고정 경로 출발점, 역할 A와 세션 세대 전환. 이전 버퍼·접근 등록 정리, 원본과 수신 이력 유지 | 실제 새 세션 위치 확인 전 “A 출발 위치 확인 중”. 외부 모드는 스크립트의 A 출발점 정렬 안내. |
| B 시작 위치로 설정 | 현재 시연에서 저장된 대상 쪽지 기준 합성 경로 600m 뒤. 이전 버퍼·등록 격리. 원본·이력 보존 | 대상 없음/경로 출발점 설정 불가 시 비활성 및 이유. 이미 B 이력이 있으면 “이미 받은 쪽지예요. 다시 받으려면 새 시연 초기화.” 전환 자체로 이력 초기화 금지. |
| 구덩이 테스트 제보 | A와 유효 표본이 필요. “도로에 구덩이가 있어요” / WARNING으로 실제 동일 저장 경로 호출. 첫 신선한 표본부터 가능 | “위치 표본 대기”·“선택할 수 있는 위치 없음”·“제보 가능”·“저장 중”·“저장 완료 · 실제 offset {값}”·“저장 실패 · {이유}”. offset은 처리 시각과 선택 표본 수신 시각의 차이. |
| GPS 입력 모드 | [웹콘솔 연동] / [외부 ADB 경로 입력] 상호 배타. “전환 중” 동안 입력이 섞이지 않도록 기존 소스 해제 확인 후 새 소스 수락 | 웹콘솔은 연결 대기/실패, mock 위치 권한 부족, 주행 입력 반영, 실제 SDK 수신을 각각 표시. 외부는 외부 입력 대기 → 실제 SDK 수신을 구분하며 패널이 재생을 시작하지 않는다. 모드 실패 시 자동 전환 없음. |
| 시연 수집 시작·중지 | 제품과 서비스 상태 공유. 중지로 수집·접근 등록·메모리 버퍼 정리 | 원본·수신 이력 유지. 외부 재생기 중지와는 구분. 위치 수신 대기·진행·실패를 현재 서비스 상태에 맞게 표시한다. |

저장 중에는 제출·A/B 전환·초기화를 비활성화하고 “저장 완료 후 조작할 수 있어요”를 버튼 근처에 둔다. 세션을 교체할 수 있는 GPS 변경·수집 중지도 같은 잠금을 적용하는 안이다. UI 잠금과 별도로 이전 세션의 늦은 이벤트는 세대 기준으로 차단해야 한다. A/B 전환 시 이전 등록이 제거되고 새 SDK 위치가 확인되기 전에는 이전 위치를 새 역할의 위치로 쓰지 않는다. 속도·기어는 웹콘솔에서만 조작한다.

## 4. 시연 스토리보드

| 순서 | 조작 | 확인할 화면과 결과 |
| --- | --- | --- |
| 1 | D1 열기 → 새 시연 초기화 → 범위 확인 후 실행 | 완료 문구. 새 시연에 남은 원본과 이력 없음. |
| 2 | GPS 모드 선택 → A 시작 위치 설정 → 수집 시작 | D1의 실제 SDK 수신 확인. 외부 ADB라면 스크립트를 A 출발점에 맞춰 별도로 시작. |
| 3 | 합성 경로로 30초 이상 이동 | D2에서 실제 수신과 이력 확인. 충분한 offset을 보여주기 위한 연출이며 제출 조건은 아니다. |
| 4 | 테스트 제보 또는 실제 연동이 검증된 Gleo 제보 | P4 → Room 커밋 → P5. 주행 규제로 디버그 조작이 잠기면 허용된 정차/주차 상태에서 제보하거나 검증된 시스템 Gleo 경로를 쓴다. 저장만을 위해 주행 규제를 우회하지 않는다. |
| 5 | D2 열기 | A 현재 위치와 저장 위치, 실제 offset 확인. |
| 6 | B 시작 위치 설정 | 동일 쪽지를 유지하고 경로 600m 뒤에서 시작. ADB라면 B 시작점에 맞춰 외부 스크립트 재배치. |
| 7 | 패널 닫기 → 같은 제품 화면에서 접근 | P3. 패널 닫기 전후 수집과 위치 입력이 계속된다. 앱이 주행 중 차단되면 시연 환경의 차단 사실을 기록하고, 허용 상태에서 표시를 확인한다. |
| 8 | 수신 조건 충족 | P7 “주의 · 도로에 구덩이가 있어요.” 같은 경로·진행 방향·전방·유효 기간·타인·미수신 및 유효 위치 검사가 필요. 계획의 150m는 프로젝트 수신 기준이며 공식 규격이나 안전 거리로 표시하지 않는다. |
| 9 | 반복 위치 또는 재접근 | 허용 상태에서 D2 확인. B의 이력 1건 유지, P7 새 수신 연출 없음. |
| 10 | 새 시연 초기화 | 원본과 이력이 초기화되어 같은 흐름 재현. B 재설정만으로는 중복 방지 상태가 유지된다. |

시연 환경은 노트북 한 대, Pleos 에뮬레이터 한 대, 앱 하나, 로컬 Room이다. 가상 역할 교체로 운전자 간 전달을 재현한다.

## 5. 공식 규제 검토표

**의무**는 플랫폼 제한 또는 공식 문서의 준수 항목, **권장**은 공식 UX 원칙, **선택**은 이 와이어프레임의 결정이다. 속도 0 또는 잠시 정차가 주차와 같은 허용 상태라는 전제를 두지 않는다. 플랫폼 상태가 미확인인 동안에는 제한 가능성이 있는 행동을 잠그고, 주행 중 카드 표시 가능성도 검증 전 보류한다.

[Display Guide 2.15](https://www.figma.com/design/rOCMHvm1HfO67Qz96CX1K2/Pleos_Connect_display_guide_215)와 [Design Assets 2.15](https://www.figma.com/design/nBFUUrFs1eWQUOXlfUES5M/Pleos_Connect_design_assets_215)는 접근 거부로 내부를 열지 못했다. 자산 매핑에 필요한 것은 두 파일의 열람 가능한 링크 또는 관련 프레임·토큰 내보내기다.

UI Design Guide의 주요 텍스트 물리 높이는 한국어판 5mm, 영어판 4mm로 다르다. 해당 기기·지역 기준을 확인하기 전 치수는 확정하지 않는다. 대비 4.5:1, 지연 시 처리 피드백, 3줄 제한은 해당 원문 조건에 맞춰 검증한다. 영어 문자 수를 한국어 표시 상한으로 환산하지 않는다.

## 8. 저장소 차이와 미확정 사항

- 검토 자료는 `docs/plans/implementation-plan.md`, `docs/specs/road-notes/00-overview.md`, `02-location-buffer.md`, `03-save-road-note.md`, Compose `LocationView`·`LocationViewModel`, Manifest다. 기존 UI는 상태와 시작·중지·권한 설정을 보여준다. ViewModel은 FGS Binder 상태를 연결하고 초기값은 STOPPED다. 45초 버퍼와 표본 선택은 현재 범위다. 저장, 후보·수신, 최종 화면, 디버그 패널과 GPS 두 모드는 구현 완료 근거가 없다.
- 기존 정본 일부의 300m B 출발과 REPLAY/DemoClock은 00 개요 및 이번 요청과 다르다. 와이어프레임은 요청대로 **600m**, 웹콘솔 또는 외부 ADB를 사용한다. 정본 변경은 별도 합의다. 배치 시점은 최신 버퍼 스펙의 Main 직렬 선택 진입 시각을 적용하며, Gleo 외부 수신 시각과 구분한다.
- 150m, 후보 조회 거리·주기·등록 상한, 수신 정확도 및 신선도는 계획값이다. 최신 버퍼 저장 신선도와 수신 후보 신선도는 서로 다른 조건이다. 도로/차선 식별·방향·경로 매칭은 합성 경로 계약에서 검증하고 실제 도로 정확도로 일반화하지 않는다.
- 정본의 시연 TTL 10분과 저장 단계 리뷰의 TTL 책임, 중복 비교 필드, source 허용값은 동기화 필요. TTL 만료 PENDING의 화면 공개 여부, 동률/다건 선점, 이미 보인 카드의 종료 조건, 정확한 가시성·ACK 경계, 시연 대상 선택(예시는 현재 시연의 최근 성공 건), 600m 출발점이 경로 밖일 때 처리, 모드 변경 뒤 수집 재개 방식도 검토가 필요하다.
- 정식 사용자용 UX 구조를 설계했지만 현 저장 계약은 합성 데이터 영속화만 허용한다. 실제 위치 영속화·개인정보 동의·보존과 실제 사용자 간 전달은 출시 전 별도 계약이다.
