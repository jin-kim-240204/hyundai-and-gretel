# 작업 및 검증 기록

작업마다 <작업명>.md에 요청/수정범위/선택규칙/구현결정/실패수정/남은사항을 남기고, <작업명>.json에 다음 형식의 결과를 기록한다.

```json
{
  "task": "작업명",
  "selected_rules": ["VEH-01"],
  "checks": [
    {"id": "VEH-01", "status": "NOT_TESTED", "evidence": "권한 거절 테스트 미실행"},
    {"id": "DOC-4803b04e4b28#사용함수별권한", "status": "NOT_TESTED", "evidence": "실제 함수와 Manifest 대조 필요"}
  ]
}
```

각 원문 요구사항은 DOC-<12자리 페이지해시>#<항목명>으로 나눈다. evidence에는 원문 절/도해와 코드 파일/줄 또는 재현 명령/환경/로그/이미지를 연결한다. 규칙 적용 제외에는 이유를 쓴다. PASS는 실제 증거가 있을 때만 쓴다. 예시 JSON은 완료 보고서가 아니다.

정적 검사 PASS와 전체 제품 적합성 PASS는 다르다. 수동 검증 미실행은 NOT_TESTED로 보존하며 스크립트는 종료코드 2를 반환한다. FAIL은 1, 기록된 범위가 모두 PASS/N/A이면 0이다.
