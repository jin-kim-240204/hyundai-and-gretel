# 도로 쪽지 시연 안내

**작성만 한 대본이다. 현재 앱/Studio/adb/기기/에뮬레이터/계측 실행은 금지이며 실제 시연은 NOT_TESTED다.** 아래 조작은 별도 실행 허용 이후에만 한다. 이번 제출은 구현과 host/빌드·정적 검사 근거이며 주행 성공·실차 안전·심사 적합 판정이 아니다.

## 고정 빌드와 화면의 역할

검증한40자리 commit·APK SHA256·debug/release variant·JDK/SDK·Pleos/AVD/ABI·권한/실제 CarUx·입력 모드를 먼저 기록한다. 원래 작업 디렉터리의 polling dirty가 들어간 APK를 검증 빌드와 혼용하지 않는다. 정확한 커밋 검증은 [07 §5](specs/road-notes/07-integration-and-demo.md#5-정확한-커밋-head-검증-계획--실행은-승인-후) 및 [07 검사 기록](work/step07-integration-verification.md)을 따른다.

- 제품 화면: 수집 시작/중지, 제보 결과, 수신 상태와 recipient 전체 JOIN의 한 건 카드, 명시 확인. 패널이 닫혀도 업무는 유지한다.
- debug ‘시연 도구’: A/B·입력 모드·선택 역할 시작 위치·구덩이 테스트 제보·새 시연 초기화/확인·진단·합성 진행축. 파랑은 실제 SDK 수락 위치, 빨강은 현재 시연 원본 위치이며 지도/센서 accuracy가 아니다.
- 웹콘솔: 속도/기어만 제어한다. 콘솔의 숫자 변경이나 provider 호출 성공은 SDK 수신 성공이 아니다.
- release: 제품 화면/기존 SDK·전체 수신함/명시 확인은 유지하지만 debug 패널/fixture/mock/웹콘솔 입력은 없다. release로 A/B 시연이 가능하다고 주장하지 않는다. 현재 release 산출물은 unsigned이며 배포·설치 검증 결과가 아니다.

MainActivity에 DO activity metadata를 선언했다. 이 선언과 KEEP_SCREEN_ON·FGS·CarUx 제한은 별개다. 실제 주행 표시 효과는 아직 확인하지 않았다. NO_SETUP/미연결에서는 역할·모드·시작 위치/reset/시연 입력 시작을 막으며 중지/취소/닫기를 유지한다. P/속도0만으로 설정 허가를 판단하지 않는다. DO가 있어도 본문/문자·항목/깊이·NO_VIDEO 제한은 유지한다. 전체 화면이 속도 증가만으로 사라지는 문제와 제한된 콘텐츠 보류를 구분해 기록한다.

## 준비 — 허용 후에만

1. 노트북1·Pleos 에뮬레이터1·앱1개/동일 Room DB를 사용한다. 합성 데이터만 준비하고 실제 사용자 위치/제보 원문을 원격 보고에 올리지 않는다.
2. 테스트 앱을 mock 위치 제공자로 선택할 수 있는 환경인지와 SDK 위치 권한/Android 위치 설정·알림을 각각 확인한다. 앱은 스스로 권한/app-op을 승격하지 않는다. 웹모드는 단독 mock writer, 외부 모드는 앱 provider 정리 완료가 전제다.
3. 웹콘솔 경로는 `http://127.0.0.1:8088/vehicle/state`, `controls.speed_kph`, `gear.actual.value`다. 기존 관찰 형식이며 공식 안정 API 보장이 아니다. 접속/응답 형식이 다르면 오류로 두고 환경을 확인한다. 임의 주소나 직접 Fake 위치로 대체하지 않는다.
4. 최신 구조의 새v1으로 기준을 재설정했다. 이전 개발1~4 DB가 있는 설치본은 최초 실행 전 앱 데이터 전체를 초기화한다(현재 실행 금지라 이번에는 수행하지 않음). 이후 새v1의 소속 없는 행/다른 시나리오와 현재 시나리오를 구분하며, 시연 reset은 현재 소속만 삭제한다.

## 명시 외부 ADB 모드 대본

현재 실행하지 않는다. 나중에 허용되면 다음 순서로 재현한다.

1. 명시 ‘외부 ADB 입력’ 선택. 앱 콘솔 읽기/이전 provider 정리가 확인된 뒤 시작한다. 정리 실패는 모드 전환 성공이 아니다.
2. 패널에 표시된 progress의 probe 좌표를 외부 재생기로 주입하고 실제 SDK probe 확인을 기다린다. 그 뒤 요청 target을 주입해 SDK 목표 확인을 기다린다. 각 단계15초·5m gate, 준비점25m 이격을 지킨다.
3. 이후 외부 D 정방향 경로를 순차 재생한다. 명령 형식은 경도→위도 순 `adb -s <serial> emu geo fix <longitude> 37.5`. progress 변환은 `127.02 + degrees(progress / (6371000 * cos(radians(37.5))))`다. 경로 끝을 넘으면 중지하고 clamp/loop/역방향을 만들지 않는다.
4. 외부 serial·목표·준비점·진행 속도는 명시 입력이고 명령 반환만으로 SDK 수락을 판단하지 않는다. 앱 중지와 외부 재생기 중지는 별개이므로 발표자가 외부 입력도 종료한다.

웹모드 실패에서 외부 모드로 자동 전환하지 않는다. 이 문서는 조작/스크립트 입력 계약의 초안이며 실행 가능한 재생 스크립트를 이번에 만들거나 실행하지 않았다.

## 실패·수명 및 주행 화면 확인

- P→D/속도 증가→정차, 주행 중 재진입·홈 복귀/재생성·분할 화면에서 제품 Activity가 사라지거나 별도 축소 화면으로 바뀌지 않는지 확인한다. metadata만으로 이 결과를 추정하지 않는다. 콘텐츠 제한/OS 정책은 별도 기록하고 우회하지 않는다.
- 권한 거절/회수·SDK null/error·provider 정리 실패는 실제 종류별로 기록한다. 입력 전체 성공 응답이2초 초과 지연되면 tick 포함 ERROR·SDK 중지, 늦은 주입0·정리 전 재시작0. 최초 prepare 검증시각도 gate가 갱신하지 않으므로 실제 SDK gate 지연과 입력 freshness가 양립하는지 확인한다. 유예값을 임의로 늘리거나 캐시를 새 표본처럼 만들지 않는다.
- 등록 전/후 onError·수신 StorageFailure는 해당 수신 세션 Failed. 위치/수락 쓰기/기존 큐는 유지하고 위치/DB 신호로 자동 복구하지 않는다. 명시 stop→새 start에서만 재허용한다.
- 저장/수신/ACK/reset 수락 후에는 역할/모드/시작/reset 설정을 거절한다. 일반 stop은 가능하고 원래 키의 수락 쓰기는 끝낸다. 수집 location/저장전용 dataSync와 마지막 쓰기 뒤 종료를 각각 확인한다.
- 실제 SDK 오류→수락 저장→마지막 unbind→알림/서비스 종료는 [4541836293](https://github.com/jin-kim-240204/hyundai-and-gretel/pull/4#discussion_r4541836293)의 미해결 근거다. Fake·종료 판단·계측 컴파일은 실제 SDK/Android 수명 성공이 아니다.
- 새v1의 동시 복합키/단일 JOIN·ACK·현재 소속만 reset/롤백은 계측 실행 허용 후 확인한다. Fake의 저장/삭제 모델은 SQLite 원자성 증거가 아니다.

각 장면은 [07 R01~07](specs/road-notes/07-integration-and-demo.md)의 PASS/FAIL/NOT_TESTED로 개별 기록한다. 현재 전부 NOT_TESTED다. 수신 중복 방지와 표시 확인을 구분하며 이번 구현의 명시 확인 ACK는 현재 검증 계약이다. 최종 읽음 정의/버튼 필수·음성 의존을 새로 확정하거나 Gleo/자동 ACK를 추가하지 않는다.
